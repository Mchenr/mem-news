# Agent Memory 周报 · 2026-10-19

观察区间：2026-10-12 至 2026-10-19（Asia/Shanghai）

## 本周摘要

- **OpenViking 默认分支连续改变 API 与分布式部署契约**：已合并但未证明发布的变更移除同步 `extract`、单次操作 `timeout` 和旧 multi-write 管理面，并把账户/认证、队列与 idle auto-commit 推向多副本部署；升级前必须按新版异步 commit 与 account-scoped 存储模型迁移。
- **Graphiti v0.31.x 正式发布 combined extraction 与调用面 Breaking Change**：批量 episode 默认一次完成 node/edge 抽取，直接调用 `extract_edges` 需要适配二元组返回；默认 OpenAI 模型也迁到 `gpt-6-luna`。发布后参考服务默认绑定从 `0.0.0.0` 改为 `127.0.0.1`，但仍没有认证，不应暴露到不可信网络。
- **Hindsight v1.0.0 收紧共享 bank 作用域，发布后继续扩展 decision model**：tag-scoped caller 不再能调用 bank-wide 控制面；默认分支又合入可选决策模型、精确 source chunks/entities 回传、按租户/operation 选择 LLM，以及 ChatGPT/NVIDIA NIM provider，但这些尚无新 Release 证明。
- **Cognee v1.6.4/v1.6.5 改变存储维护与生成依赖**：LanceDB 不再后台自动 pruning，需要运维方手动压缩；v1.6.5 发布 trace 一次性入库、代码文档图谱化、Memify API 等能力，并提高自定义 graph model generation 的依赖下限。
- **Supermemory Local 0.0.9 扩展 Linux 自托管，同时暴露迁移与租户安全边界**：发布预编译 amd64/arm64 Docker 与 v5 API；本地访问现在也要求 API key，旧 direct workflow 被移除。legacy tools 2.x 的模型可选 `containerTag` 越权已合并修复，但没有 GitHub Release 证明该修复已发布。

## 固定跟踪项目

### 1. OpenViking

- **已合并未发布 / Breaking Change**：[#6131](https://github.com/volcengine/OpenViking/pull/6131) 移除 `POST /sessions/{id}/extract`，调用方须改用异步 `/commit` 并查询 task id；[#6048](https://github.com/volcengine/OpenViking/pull/6048) 同时移除 API/SDK/CLI/MCP 的 per-operation `timeout`，超时只由 HTTP client 控制。最新 GitHub Release 仍为 [v0.5.0](https://github.com/volcengine/OpenViking/releases/tag/v0.5.0)。
- **已合并未发布 / 部署边界**：[#5741](https://github.com/volcengine/OpenViking/pull/5741) 用 account-scoped partition、segment/checkpoint、catch-up 与 GC 取代旧目录 sidecar/global sequence，并删除旧 sync-status/sync-retry 管理面；[#5955](https://github.com/volcengine/OpenViking/pull/5955) 增加 MySQL 与 Redis+MySQL Account Store，API key 以 SHA-256 digest 保存；[#6046](https://github.com/volcengine/OpenViking/pull/6046) 提供可选 Redis 分布式 idle auto-commit scheduler。
- **已合并未发布 / 数据边界**：[#6128](https://github.com/volcengine/OpenViking/pull/6128) 支持多模态 hybrid query，dense 通道可接收图片而 sparse 仍只处理文本；[#5937](https://github.com/volcengine/OpenViking/pull/5937) 让 capture filter substitutions 同时改写 tool inputs/results，避免秘密写入长期记忆；[#5578](https://github.com/volcengine/OpenViking/pull/5578) 新增 Microsoft Agent Framework `ContextProvider` 集成。

### 3. Graphiti

- **已发布功能 / Breaking Change**：[v0.31.0](https://github.com/getzep/graphiti/releases/tag/v0.31.0) 正式发布 combined node+edge extraction 默认值，以及 `extract_edges` 从 `list[EntityEdge]` 改为 `(edges, materialized_nodes)`；同时加入 opt-in Jev/OpenAI Decisions 去重 client，并将默认 OpenAI 模型改为 `gpt-6-luna`、默认关闭 prompt caching。当前 core Release 为 [v0.31.1](https://github.com/getzep/graphiti/releases/tag/v0.31.1)。
- **已合并未发布 / 部署边界**：[#2032](https://github.com/getzep/graphiti/pull/2032) 将 MCP/REST 参考服务默认绑定从所有接口改为 `127.0.0.1`。参考服务仍无认证/授权，不能因为改为 localhost 默认值就把它视为可直接公网部署。

### 5. Hindsight

- **已发布功能 / Breaking Change**：[v1.0.0](https://github.com/vectorize-io/hindsight/releases/tag/v1.0.0) 移除 `@vectorize-io/hindsight-agent-sdk` 与 OpenClaw alpha knowledge tools，并拒绝 tag-scoped caller 访问 bank-wide statistics、operations、webhooks、audit/LLM logs 等控制面；从旧版本升级需按 caller scope 与 OpenClaw 工具面重新验收。
- **已合并未发布 / 重要能力**：[#5607](https://github.com/vectorize-io/hindsight/pull/5607)、[#5613](https://github.com/vectorize-io/hindsight/pull/5613) 与 [#5284](https://github.com/vectorize-io/hindsight/pull/5284) 加入全局/按 operation 配置的可选 decision model，可使用 Jev、Cloudflare Clef 或 OpenAI Decisions 做 recall 排序、冲突处理与 consolidation triage；未配置时仍走原路径。
- **已合并未发布 / 多租户与数据边界**：[#5578](https://github.com/vectorize-io/hindsight/pull/5578) 允许按 tenant/bank/operation 扩展 LLM 请求，选择不同模型、key 与 headers；[#5678](https://github.com/vectorize-io/hindsight/pull/5678) 让 MCP recall 可选返回 source chunks/entities/source facts 以保留精确字符串和来源；[#5688](https://github.com/vectorize-io/hindsight/pull/5688) 与 [#5697](https://github.com/vectorize-io/hindsight/pull/5697) 分别加入 ChatGPT 登录 provider 和 NVIDIA NIM embedding/reranker。

### 高优先级

- [tigerless-labs/agent-memory](https://github.com/tigerless-labs/agent-memory)：约 4,177 Stars，较 10 月 12 日增加约 776，本周约 30 个默认分支提交。Markdown 仍是事实源、SQLite/FTS5 是可重建缓存；本周加入 Hermes/Muse 原生工具执行与 event-driven auto-dreaming。LongMemEval-S 仍是项目方限定子集自测，不能与完整榜单横比。
- [vshulcz/deja-vu](https://github.com/vshulcz/deja-vu)：约 1.2k Stars，本周约 78 个默认分支提交。它专注索引/召回 coding-agent 既有 session history，不依赖 LLM；公开 97.2% R@5 与复现 driver 是维护者自评，应在统一 corpus、查询和 token 预算下复验。
- [slow-stack/mneme](https://github.com/slow-stack/mneme)：约 157 Stars，本周提交数达到单页 100 条上限并发布 v0.9.0/v0.9.1。M.O. executable memory pipeline 与 reversible scope gate 有原创性；本周还把 39 条 API route 改为声明式鉴权，修复 `/export`、`/external-api` 可未授权导出归档/已遗忘数据或签发 token 的高风险边界。仍缺同口径长期记忆 benchmark。

### 继续观察

- [supermemoryai/memoryrepo](https://github.com/supermemoryai/memoryrepo)：约 100 Stars、仅 1 个提交。其 Cloudflare Durable Objects + Artifacts Git repo 让每次 memory write 成为 commit，并每四小时 dream、用乐观并发控制更新，架构有辨识度；但单提交、无公开 benchmark，暂不进入高优先级。
- [AgentMemoryRepo/agentmemoryrepo](https://github.com/AgentMemoryRepo/agentmemoryrepo)：约 803 Stars，但本周无默认分支提交。Git-native Markdown/spec 与组合式 ownership 仍值得观察，当前没有 runtime benchmark 或持续实现证据。
- [deepmemteam/deepmem](https://github.com/deepmemteam/deepmem)：约 114 Stars、共 5 个提交。本地/云端 latency 脚本可复现，但默认 workload 是 synthetic，`add` 也不是与 Mem0 同口径；LongMemEval/LoCoMo 只给出适配建议而非已提交结果。自托管 open mode 无认证，部署方必须自行隔离。

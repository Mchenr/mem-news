# Agent Memory 周报 · 2026-09-28

观察区间：2026-09-21 至 2026-09-28（Asia/Shanghai）

## 本周摘要

- **Hindsight v0.10.1 把 memory bank 迁移升级为可控复制面**：统一 transfer API 可分别携带 data、bank config 与 history，并新增单次异步 clone；附件改为 document-owned。默认复制 bank config 会连同 webhooks 一起复制，迁移与克隆前必须明确外部回调边界。
- **Mem0 发布托管 User Profiles，并收缩 Coding Agent 的默认检索强度**：Python v2.2.0 / Node v3.3.0 为 `MemoryClient` 增加按 JSON Schema 生成的异步用户画像；多款插件不再要求每题主动、多次搜索，默认改为在重复调查或复用既有结论时单次检索，直接改变 token、延迟与召回暴露率。
- **Cognee v1.6.1 扩展 Google 数据接入并修补 provenance 隔离**：发布 Drive OAuth、Gmail/shared-drive 同步、流式大图可视化，以及把文档外部元数据带入 chunk 与 hybrid retrieval；provenance 结果现在限制在调用方可读 dataset。`dlt` 升为核心依赖，是源码安装和手工依赖管理的 Breaking Change。
- **OpenViking 与 ReMe 合入但尚未证明发布的 memory maintenance 能力**：OpenViking 新增 `ov compile --skill memory`，可原地去重、合并、拆分和压缩 memory 目录；ReMe 统一文本/图片 auto-resource Agent workflow，图片默认启用，并替换旧的 image model/prompt 配置入口。
- **Graphiti 与 Supermemory 合入多租户权限修正**：Graphiti MCP 按 `group_id` 路由到对应后端 graph；Supermemory MCP 将 full-scope read grant 强制保持 read-only。两者都只证明已进入默认分支，尚无对应稳定 Release 证据。

## 固定跟踪项目

### 1. OpenViking

- **已合并未发布**：[#5178](https://github.com/volcengine/OpenViking/pull/5178) 为 `ov compile` 增加 `--skill memory` 模式，直接复用现有 memory framework，对目标 memory 目录执行去重、合并、拆分与压缩，并输出 add/update/delete diff；普通 compile 路径保持不变。
- **已合并未发布**：[#5330](https://github.com/volcengine/OpenViking/pull/5330) 为 `ls` / `tree` 增加 `has_more`，通过 N+1 探测向 CLI 与 MCP 暴露分页截断，调用方不能再把返回列表误当完整目录。
- **发布边界**：最新稳定 Release 仍为 [v0.4.21](https://github.com/volcengine/OpenViking/releases/tag/v0.4.21)，以上能力不能按已发布功能部署。

### 2. MemOS

**无关键变化。** [core v2.0.34](https://github.com/MemTensor/MemOS/releases/tag/v2.0.34) 仅给出版本发布说明，[local plugin v2.0.20](https://github.com/MemTensor/MemOS/releases/tag/memos-local-plugin-v2.0.20) 主要是 recovery、capture boundary 与 evolution 稳定性修复；本期未确认新的记忆模型、Breaking Change 或部署边界。

### 3. Graphiti

- **已合并未发布 / 多租户边界**：[#1926](https://github.com/getzep/graphiti/pull/1926) 让 MCP tool 按请求的 `group_id` 获取独立 driver/client；`get_episodes` 跨 group 合并结果，`clear_graph` 逐 group 清理，避免非默认 group 错落到默认 graph。
- **兼容性边界**：[#1921](https://github.com/getzep/graphiti/pull/1921) 将 MCP server 从 MCP SDK 1.x / FastMCP 迁到 MCP SDK 2.x / `MCPServer`，最低 `graphiti-core` 提升至 0.30.2；最新 MCP Release 仍为 [mcp-v1.1.0](https://github.com/getzep/graphiti/releases/tag/mcp-v1.1.0)，升级方应等待或固定未发布源码版本。

### 4. Letta

**无关键变化。** 固定仓库 `letta-ai/letta` 的最新 GitHub Release 仍为 [v0.16.8](https://github.com/letta-ai/letta/releases/tag/0.16.8)，官方 commit feed 在本期没有默认分支条目；不把其他 Letta 仓库活动混入结论。

### 5. Hindsight

- **已发布功能**：[v0.10.1](https://github.com/vectorize-io/hindsight/releases/tag/v0.10.1) 统一 bank transfer export/import，以 `include_data`、`include_bank_config`、`include_history` 三个 scope 控制迁移内容，并新增一致性快照上的单次异步 clone。旧 document-transfer 入口保留形状但已标记 deprecated。
- **部署与数据边界**：clone 默认携带 bank config，因此也会复制 webhooks；导入的 pending/processing operation 会恢复为 cancelled，避免重放 source bank 的 retain 或 webhook。附件改为 document-owned，放弃跨文档 dedup；迁移无法归属到 document 的旧 store-owned attachment 会被删除。
- **Agent / benchmark 边界**：coding-agents [v0.7.0](https://github.com/vectorize-io/hindsight/releases/tag/integrations%2Fcoding-agents%2Fv0.7.0) 增加 `autoInject=reflect|pages|recall|none`。项目同时用固定 `AMB_REF` 的 Agent Memory Benchmark launcher 替换仓库内 LoCoMo/LongMemEval runner；这提高基准版本可追踪性，但历史曲线与新 runner 的条件仍需逐项对齐。

### 6. Mem0

- **已发布功能 / 平台边界**：[Python v2.2.0](https://github.com/mem0ai/mem0/releases/tag/v2.2.0) 与 [Node v3.3.0](https://github.com/mem0ai/mem0/releases/tag/ts-v3.3.0) 为托管 `MemoryClient` 增加 User Profiles：按项目级 JSON Schema 异步生成用户画像，并用 Idempotency-Key 避免重试启动重复 job。该入口不证明 OSS `Memory` 获得同等 profile engine。
- **默认行为变化**：Pi、OpenCode、OpenClaw、DeepSeek 等 9 月 23 日插件发布不再要求每个可能依赖历史的问题都主动或并行多次搜索，改为在重复调查或复用既有决定、修复、命令和结果时搜索；成本下降的同时，自动召回覆盖率也可能下降。
- **正确性 / 兼容性**：[Python v2.2.1](https://github.com/mem0ai/mem0/releases/tag/v2.2.1) 不再把 vector store 拒绝的记录报告为成功，全部拒绝时改为抛出 `VectorStoreError`；Turbopuffer 过去静默丢弃的过滤操作符现被执行，未知操作符改为报错，既有调用需检查异常和结果集变化。

### 7. Cognee

- **已发布功能**：[v1.6.1](https://github.com/topoteretes/cognee/releases/tag/v1.6.1) 发布 Google Drive OAuth、Gmail 与 shared-drive 同步，并把 `/visualize/json` 改为分块流式响应，降低大 subgraph 的峰值内存。
- **检索与安全边界**：`external_metadata` 现在随文档写入 chunk 并出现在 hybrid retrieval 结果；provenance graph 被限制到调用方可读 dataset，修复 dataset orientation 信息越界风险。
- **Breaking Change / 部署边界**：`dlt` 从可选 CSV loader 依赖升为核心依赖；GLiNER 改为首次使用时安装 CPU Torch。源码安装、离线镜像与禁止运行期下载的环境需要重新冻结依赖和镜像。

### 8. ReMe

- **已合并未发布 / 默认行为变化**：[auto-resource #555](https://github.com/agentscope-ai/ReMe/pull/555) 统一文本与图片的 AgentWrapper workflow，图片默认 `include_images=true`；旧 image Step 的 `as_llm` / 自动 `as_llm.vision` 选择被 wrapper binding 替代，`user_message` 配置改名为 `resource_instructions`。关闭图片会同时跳过删除事件，重新启用也不会自动补放，需要显式重提路径。
- **发布边界**：最新稳定 Release 是 [v0.4.1.12](https://github.com/agentscope-ai/ReMe/releases/tag/v0.4.1.12)，发布时间早于本期窗口；上述配置迁移仍只按已合并未发布处理。

## 新兴项目雷达

本期创建时间边界为 2026-05-31 之后。Stars 为 2026-09-28 官方 GitHub 项目页快照，只用于发现关注度；GitHub API 搜索受限，候选来自官方 HTML search 的 15 个关键词结果与 54 个 topic 结果，存在重叠且未穷举全部分页。

### 高优先级

- [tigerless-labs/agent-memory](https://github.com/tigerless-labs/agent-memory)：2026-09-01 创建，1,327 Stars，MIT。Markdown 是事实源，SQLite/FTS5 是可重建缓存，支持 BM25、可选 vector RRF、时间有效性、provenance trace 与独立 sleep-time consolidation。公开的 LongMemEval-S 是 120 episodes 的有界实验，项目明确声明绝对分数不可与完整公开榜单横比，这一证据边界比单报高分更可信。
- [okf-memory/okf-agent-memory](https://github.com/okf-memory/okf-agent-memory)：2026-09-05 创建，730 Stars，MIT。以 AGENTS.md 的规范性 push layer 加 OKF v0.2 的按需 pull layer 组成 dual-memory，并保留 provenance、trust tier 与 Git review；`<300µs` BM25 和约 4ms graph validation 是项目自报微基准，尚不能替代长期记忆问答评测。
- [JordyZomer/lemmalog](https://github.com/JordyZomer/lemmalog)：2026-08-27 创建，323 Stars。把 Agent Memory 建模为带 provenance 的 Datalog deductive database，含分层规则、增量推导、magic-set demand evaluation 与 BM25/entity graph 混合检索；已有 LongMemEval oracle-split runner，但 README 仅报告一次 scored run，需多次复现并固定模型与 judge。
- [libingzheren/Jev-Mem](https://github.com/libingzheren/Jev-Mem)：2026-09-20 创建，106 Stars，MIT，并同步发布 [论文](https://arxiv.org/abs/2609.23986)。其 System One controller 在 semantic、temporal、causal、entity 四类关系图之间做写入与检索决策；LoCoMo 的质量、构建速度和延迟为论文自报，仓库 quickstart 不等于复现完整实验。

# Agent Memory 周报 · 2026-09-21

观察区间：2026-09-14 至 2026-09-21（Asia/Shanghai）

## 本周摘要

- **OpenViking v0.4.21 收紧检索参数语义并调整容器持久化边界**：MCP `search` 在默认 `mode="list"` 下不再静默忽略 context-only 参数，而是直接报错；Docker 默认工作目录改为持久化挂载内的 `/app/.openviking`。同时新增远程 VikingDB glob、Hermes/MiMo/WorkBuddy 接入和私有网关 header。
- **Hindsight v0.10.0 把知识库管理正式暴露给 Agent**：发布原生 Knowledge Base MCP CRUD、mental model 触发参数、按 bank 关闭文本检索的纯向量模式，以及包含 Knowledge Base 的文档转移；这扩大了 Agent 自主管理长期知识的可用面。
- **Cognee v1.6.0 强化本地无 Key 与管线恢复**：无云端 LLM Key 时可显式下载本地模型并跳过需要 LLM 的阶段，管线崩溃后保留已完成文档；图片、音频和 embedding 模型完成端到端绑定，并按 dataset 记录 embedding 模型以阻止静默混用。
- **Cognee 同时带来部署 Breaking Change**：默认 Docker 镜像移除 GLiNER，依赖该组件的部署必须自行安装；数据库和向量适配器重构要求自托管或自定义 adapter 用户复核兼容性。
- **Mem0 将调用来源识别固化到 SDK/插件发布**：Python/Node SDK、CLI 和多款 Agent 插件统一传播 `X-Mem0-Source`、`X-Application`、`X-Mem0-Client`；OpenCode 遥测 `source` 标签改变，既有 PostHog 查询需迁移。该变化改善多层 wrapper 可观测性，但也扩大了平台侧来源元数据边界。

## 固定跟踪项目

### 1. OpenViking

- **已发布功能**：[v0.4.21](https://github.com/volcengine/OpenViking/releases/tag/v0.4.21) 增加远程 VikingDB glob、Hermes 独立 memory provider、MiMo/MiMoCode 与 WorkBuddy 日志源、私有网关 header，并改善插件 hook 与 MCP proxy 连接管理。
- **Breaking Change**：MCP `search` 默认 `mode="list"` 时，`max_tokens`、`purpose`、`detail`、`exclude_uris`、`peer_scope` 等 context-only 参数从“被静默忽略”改为参数错误；调用方必须显式使用 `mode="context"` 或移除这些字段。
- **部署边界**：Docker 默认工作目录变为 `/app/.openviking`，相对存储路径因此落入持久化挂载；依赖 `/app` 作为 cwd 的脚本需改用绝对路径或显式 cwd。远程 VikingDB 会截断超长 string/text 字段，不能再依赖超长 abstract 精确匹配。

### 5. Hindsight

- **已发布功能**：[v0.10.0](https://github.com/vectorize-io/hindsight/releases/tag/v0.10.0) 将 Knowledge Base CRUD 暴露为原生 MCP tools，允许 Agent 管理知识页；mental model 核心触发参数也可经 MCP 配置。
- **检索与迁移边界**：每个 bank 可用 `enable_text_search` 关闭文本检索以运行纯向量 recall；文档转移现在可导出 Knowledge Base，并修复 mental model evidence ID 重映射。迁移验证应覆盖知识页、mental model 证据链和 bank 级检索配置，而不只检查 memory units。
- **成本与运维**：Release 同时加入 reranker failover、通用 embedding 输入 token 上限、per-operation LLM extra body、ServiceMonitor 和可扩展 Helm sidecar/initContainer；这些能力改变部署可观测性与召回预算，但官方 benchmark 数字仍需同模型、同预算复验。

### 6. Mem0

- **已发布 SDK / 插件**：[Python SDK v2.1.0、Node SDK v3.2.0 及 9 月 18 日插件组](https://github.com/mem0ai/mem0/releases) 统一传播 `X-Mem0-Source`、`X-Application`、`X-Mem0-Client`，保留外层 wrapper 身份并追加完整调用链；CLI 与 Vercel provider 继承同一语义。
- **兼容性边界**：OpenCode v0.4.0 把 PostHog `source` 从字面量 `plugin` 改为 `OPENCODE_PLUGIN`，现有 dashboard/filter 需要迁移；项目哈希改为加盐。OpenClaw v1.2.0 等插件新增 `keyFingerprint`，安装计数从每次激活改为按 key 去重。
- **数据边界**：新增 header 与遥测字段用于平台侧来源归因，不是新的记忆检索算法；安全评审应把 wrapper 链、应用身份、加盐项目哈希和环境变量注入纳入元数据盘点。

### 7. Cognee

- **已发布功能**：[v1.6.0](https://github.com/topoteretes/cognee/releases/tag/v1.6.0) 支持无云端 LLM Key 的显式本地模型下载与阶段跳过，管线在崩溃恢复时保留已完成文档；图片/音频模型完成端到端 wiring，新 `cognee-mcp` client/server 加强外部 recall/summary 集成。
- **检索正确性边界**：每个 dataset 记录创建向量时使用的 embedding 模型，复用或更新时检查一致性，避免不同 embedding 空间被静默混用。
- **Breaking Change / 部署边界**：默认 Docker 镜像移除 GLiNER；数据库与向量 adapter 重构可能影响 Postgres、hybrid backend 和自定义 adapter。遥测外发前会对 dataset 名称做 fingerprint，但错误遥测会携带完整 route，部署方仍应复核隐私策略。

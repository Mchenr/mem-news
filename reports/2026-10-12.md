# Agent Memory 周报 · 2026-10-12

观察区间：2026-10-05 至 2026-10-12（Asia/Shanghai）

## 本周摘要

- **OpenViking v0.5.0 把记忆接入扩展为模型 API 网关，同时改变默认上下文责任**：Gateway Beta 通过 Anthropic Messages、OpenAI Chat Completions 与完整历史 Responses 原协议注入记忆；Working Memory 改为默认关闭、宿主管理历史与压缩。网关隐藏工具循环默认不限轮数、总时长和 token，非流式调用还会在客户端断开后继续运行，生产部署必须显式设限。
- **Graphiti 在默认分支准备 core 0.31.0，并改变批量抽取默认值**：bulk ingestion 默认从分离 node/edge 抽取切到单次 combined extraction，`extract_edges` 返回类型改为二元组；同时加入按 prompt/model/provider 路由的 `LLMRuntime`。GitHub 最新 Release 仍是 v0.30.2，不能把 0.31.0 当作已由 GitHub Release 证明发布。
- **Hindsight v0.10.3 强化共享 bank 的 tag 作用域与评测基线**：知识树、实体图与读写可按 caller tag scope 隔离，并加入 BEIR nDCG/Recall floor；发布后默认分支又移除了 OpenClaw 的 alpha knowledge tools，并补齐 scoped caller 对 bank-wide 审计、webhook、operation 等接口的拒绝逻辑。
- **Cognee v1.6.3 发布时间检索与多租户边界变化**：时间窗口改为包含边界日期，`temporal_cognify` 被移除，嵌套 agent 被禁止；默认分支随后合入整库 `BROAD` 检索和 opt-in 事实冲突 review，但这两项尚无对应 Release 证明。
- **Supermemory 默认分支迁移到 v5 API，工具调用面出现 Breaking Change**：`@supermemory/tools` 3.0 用 `namespace` 取代 `containerTags/projectId`，移除 `@supermemory/ai-sdk`；MCP 也转向 v5 SDK。自托管 server 最新 GitHub Release 仍是 0.0.8，仓库集成迁移不等于本地 server 已发布同等能力。

## 固定跟踪项目

### 1. OpenViking

- **已发布功能**：[v0.5.0](https://github.com/volcengine/OpenViking/releases/tag/v0.5.0) 新增 Gateway Beta。客户端只需替换 base URL 与网关 key，网关按原协议转发、检索并注入 OpenViking 记忆，同时可在服务端执行带 `openviking_` 前缀的 MCP 工具；Docker、Compose 与 Helm 均增加网关部署入口。
- **Breaking Change / 默认行为**：Working Memory 默认由开改为关；commit 仍归档原始消息并抽取长期记忆，但不再默认生成 archive overview/checkpoint。旧配置序列化时可能省略显式 `true`，升级后需要重新开启；Claude Code、Codex、OpenCode、pi、OpenClaw 等插件默认改由宿主管理历史与压缩。
- **部署边界**：网关隐藏工具循环的 round、总时长和 token 默认均无限制，且非流式客户端断开不会停止循环；应在 context profile 显式设置 `tool_max_rounds`、`tool_total_seconds` 或 `tool_total_tokens`。网关还要求独立的 Fernet encryption key 与至少 32 字符的 admin token。
- **已合并未发布 / 安全**：v0.5.0 发布后合入的 [#5864](https://github.com/volcengine/OpenViking/pull/5864) 将远程资源 DNS 校验从 fail-open 改为 fail-closed，堵住解析失败后重新解析到内网地址的 SSRF 绕过路径；尚未证明进入后续 Release。

### 2. MemOS

- **已合并未发布 / Breaking Change**：[#2479](https://github.com/MemTensor/MemOS/pull/2479) 把 summary/material 与 raw-file 邻接关系从图边迁到 node metadata，使无 edge 能力的替代图后端仍能完成存储、去重、删除、合并与 feedback locking；但替代后端不再提供 `SUMMARY`、`MATERIAL`、`PRECEDING`、`FOLLOWING` edge 操作。最新稳定 Release 仍为 [v2.0.34](https://github.com/MemTensor/MemOS/releases/tag/v2.0.34)。

### 3. Graphiti

- **已合并未证明发布 / Breaking Change**：[#1964](https://github.com/getzep/graphiti/pull/1964) 让 `add_episode_bulk` 默认采用 combined node+edge extraction，每个 episode 一次 LLM 调用；要保留旧行为需显式 `use_combined_extraction=False`。self-edge、去重和时间边输出也会变化。
- **兼容性边界**：[#1985](https://github.com/getzep/graphiti/pull/1985) 把包版本准备为 core 0.31.0，并确认直接调用 `extract_edges` 的代码需要从 `list[EntityEdge]` 迁到解包 `(edges, materialized_nodes)`。GitHub 最新 Release 仍是 [v0.30.2](https://github.com/getzep/graphiti/releases/tag/v0.30.2)，因此本报告不把 0.31.0 记为已发布。
- **已合并未证明发布**：[#1778](https://github.com/getzep/graphiti/pull/1778) 新增 opt-in `LLMRuntime`，可按 prompt 或 prompt group 路由到不同模型与 provider，并覆盖 prompt 文本；旧构造路径保持不变，但自定义 client 在新 runtime 下必须接受 `model=` 参数，多 transport token 目前不会完整计入默认 tracker。

### 4. Letta

**无关键变化。** 固定仓库 `letta-ai/letta` 在观察窗口没有默认分支提交或已合并 PR，最新 GitHub Release 仍为 [v0.16.8](https://github.com/letta-ai/letta/releases/tag/0.16.8)。

### 5. Hindsight

- **已发布功能 / 多租户边界**：[v0.10.3](https://github.com/vectorize-io/hindsight/releases/tag/v0.10.3) 为共享 bank 增加 per-caller tag scope，知识树/搜索、实体列表/详情/图以及读写路径可按 tag 约束；同时加入 BEIR retrieval baseline 与 nDCG/Recall floor。Release 汇集了多个版本间 PR，采用方应按具体包与集成核对版本。
- **已合并未发布 / Breaking Change**：[#5462](https://github.com/vectorize-io/hindsight/pull/5462) 删除 `@vectorize-io/hindsight-agent-sdk` 与 OpenClaw 的 `agent_knowledge_*` alpha tools；`enableKnowledgeTools` 仅作为 deprecated、ignored 配置保留，OpenClaw 只保留 auto-recall/auto-retain。
- **已合并未发布 / 安全**：[#5463](https://github.com/vectorize-io/hindsight/pull/5463) 对 tag-scoped caller 拒绝 bank-wide statistics、operation、webhook、audit/LLM log、alias、mission、template 等读写，避免通过 bank profile 权限读取其他 scope 的 payload 或 prompt；该修复晚于 v0.10.3。

### 6. Mem0

- **已合并未发布 / 安全**：[#7506](https://github.com/mem0ai/mem0/pull/7506) 停止 Google Matching Engine 在 DEBUG 日志中输出完整 `kwargs` 与 config dump，避免内联 `service_account_json` 的 PEM 私钥进入日志；现在只记录字段名。窗口内没有新 GitHub Release，最新 Release 仍为 [Node SDK v3.3.1](https://github.com/mem0ai/mem0/releases/tag/ts-v3.3.1)。

### 7. Cognee

- **已发布功能**：[v1.6.3](https://github.com/topoteretes/cognee/releases/tag/v1.6.3) 发布更精确的 temporal search：`since/until X` 包含边界日期，时间锚点按窗口贴合度重排；natural-language search 返回匹配 rows，Notion ingestion 移除深度上限。
- **Breaking Change / 部署边界**：移除 `temporal_cognify`；禁止嵌套 agent 与 agent 创建 agent；`dlt` 暂时固定 `<1.31`。自管依赖、agent 层级或旧配置的部署需要迁移。
- **已合并未发布**：[#5287](https://github.com/topoteretes/cognee/pull/5287) 新增 `BROAD` 整库检索，模型在只读 SQLite `SELECT` 与 bounded reading 之间选择；大于默认 32 MB 的数据集只采样相似 chunks，因此 count 被明确标为 lower bound。项目自报 NarrativeQA 132 题为 107/132，条件是 gpt-5.6-luna、GLiNER + fastembed，尚未独立复验。
- **已合并未发布**：[#5534](https://github.com/topoteretes/cognee/pull/5534) 新增默认关闭的 `improve(review_conflicts=True)`，按 `effective_date` 把事实标为 current/superseded/conflicting 并在搜索结果显示冲突；旧 contradiction/`valid_to` 机制被移除但存量字段不迁移、仅被忽略。

### 8. ReMe

- **已合并未发布 / 数据边界**：[#574](https://github.com/agentscope-ai/ReMe/pull/574) 在 `include_images=true` 时原样保存 Base64 图片到 `{session_dir}/images/`，在 note frontmatter 合并 `source_images` 并保持文本/图片顺序与来源链接。HTTP 图片仍保留远程 URL，source JSONL 仍不包含 Base64；失败调用后附件也会留存。该能力默认关闭，最新稳定 Release 为观察窗口前一天发布的 [v0.4.1.13](https://github.com/agentscope-ai/ReMe/releases/tag/v0.4.1.13)。

### 9. Supermemory

- **已合并未发布 / MCP 边界**：[#1783](https://github.com/supermemoryai/supermemory/pull/1783) 把 MCP 主路径迁到 v5 SDK，同时保留已 deprecated 的 snake_case tool alias 与旧 `activeContainerTag` 存储键；graph data 与 `/v3/session` 因无 v5 替代仍走 v3。[#1790](https://github.com/supermemoryai/supermemory/pull/1790) 把 destructive `forget_memory` 单独暴露为工具。
- **发布边界**：最新自托管 GitHub Release 仍为 [server-v0.0.8](https://github.com/supermemoryai/supermemory/releases/tag/server-v0.0.8)；默认分支与 npm SDK 的 v5 迁移不能外推为 OSS server Release。

- [tigerless-labs/agent-memory](https://github.com/tigerless-labs/agent-memory)：增至约 3,401 Stars（9 月 28 日为 1,327），本周 12 个默认分支提交。继续以 Markdown 为事实源、SQLite/FTS5 为可重建缓存，并完善 Claude Code/Codex/Muse 共用 store 的 host preflight。公开 LongMemEval-S 是 120 episodes、每题最多 12 sessions 的 write+read 端到端实验，项目明确说明绝对分数不可与完整榜单横比。
- [vshulcz/deja-vu](https://github.com/vshulcz/deja-vu)：约 1,176 Stars，本周高频提交并新增 Agent Memory Leaderboard Add/Search adapter、跨 41 个 coding agents 的本地 session history，以及可复现 benchmark 入口。它更接近“既有会话索引/召回”而非主动 memory evolution；97.2% R@5 等数字仍是维护者自测，需要统一 corpus、查询与 token 条件复验。
